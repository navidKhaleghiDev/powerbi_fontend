# راه‌اندازی کامل با Docker Compose

این مسیر یک محیط محلی مستقل برای PostgreSQL → Debezium → Kafka → ClickHouse → داشبورد می‌سازد. دادهٔ اولیه مصنوعی و مشخص است؛ رابط قدیمی و داده‌های نمایشی حذف‌شده برنمی‌گردند. اعداد داشبورد از پایگاه واقعی داخل کانتینرها خوانده می‌شوند، پس از آنکه بررسی انتهابه‌انتها موفق شود.

## پیش‌نیاز

Docker Engine و افزونهٔ Compose باید نصب و فعال باشند و حساب شما به socket دسترسی داشته باشد. روی این Ubuntu:

```bash
sudo apt-get update
sudo apt-get install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
sudo usermod -aG docker navid
```

برای اعمال گروه، دوباره وارد نشست شوید. در نشست فعلی اگر ابزار فعال‌سازی گروه موجود نیست، مدیر می‌تواند موقتاً گروه socket را به گروه شخصی navid تغییر دهد؛ socket را برای همه قابل‌نوشتن نکنید.

## اجرا

در پوشهٔ پروژه:

```bash
cd /home/navid/work/powerBI/control-center
npm install
npm run stack:init
npm run stack:up
npm run stack:provision
npm run stack:verify
```

`stack:up` ابتدا تصویر برنامه را می‌سازد و تا سلامت سرویس‌ها صبر می‌کند. اولین اجرا به اینترنت برای دریافت تصاویر نیاز دارد. اگر بررسی سلامت تمام نشد، `npm run stack:logs` را ببینید.

`stack:provision` حساب‌ها، اتصال، جریان CDC، نگاشت، snapshot، تعریف شاخص، تأیید، تطبیق و گزارش منتشرشده را از طریق منطق و APIهای خود برنامه آماده می‌کند. تنها در کانتینر اختصاصی محیط محلی اجرا می‌شود. این فرمان به برنامهٔ میزبان یا پایگاه‌های خارجی شما دست نمی‌زند.

## ورود

نشانی پیش‌فرض محیط Compose:

http://172.16.10.15:3003/fa/login

نام حساب‌ها `local_provider` و `local_customer` است. رمزها تصادفی‌اند؛ برای دیدن آن‌ها روی میزبان اجرا کنید:

```bash
cat .data/compose-access.txt
```

این فایل را عمومی نکنید. حساب اول هر دو پنل را می‌بیند؛ حساب مشتری فقط تحلیل را می‌بیند. برنامهٔ فعلی روی پورت ۳۰۰۱ با حساب‌ها و اطلاعات قبلی باقی می‌ماند. تنظیم BI_APP_PORT در فایل خصوصی .env.compose پورت این محیط را تعیین می‌کند؛ پورت اشغال‌شده را انتخاب نکنید.

## داده و داشبورد ساخته‌شده

- پایگاه منبع: bi_source؛ جدول sales.orders با کلید order_id و چند سفارش مصنوعی.
- کاربر منبع bi_cdc مجوز replication و مالکیت جدول موردنیاز را دارد؛ حساب مدیر PostgreSQL برای اتصال برنامه استفاده نمی‌شود.
- انبار: bi_warehouse؛ دادهٔ خام و snapshotهای اختصاصی برنامه در ClickHouse.
- چهار شاخص: تعداد رکورد، تعداد مشتری متمایز، تعداد سفارش متمایز و جمع مبلغ سفارش‌ها.
- چهار کارت شاخص و چهار نمایش: مبلغ بر اساس شهر، روند روزانه، وضعیت سفارش و جدول مشتریان.
- ارقام شامل همهٔ وضعیت‌های سفارش و با واحد تمرینی USD هستند؛ درآمد قطعی، سود یا حسابداری واقعی سازمان نیستند.
- گزارش با نام «داشبورد سفارش‌های پایگاه محلی» در پنل تحلیل قرار می‌گیرد.

## بررسی انتقال تغییرات

```bash
npm run stack:exercise
npm run stack:verify
```

فرمان exercise در پایگاه محلی ردیف‌های اختصاصی cdc-proof-* را درج، اصلاح و حذف می‌کند؛ رسیدن رویدادها به ClickHouse و وضعیت نهایی منتشرشده را بررسی، ارقام را دوباره تطبیق و گزارش را تازه می‌کند. این فرمان روی دادهٔ مصنوعی اثر واقعی دارد و پس از آن ارقام اولیه تغییر می‌کنند؛ تکرار آن ردیف‌های تجاری دیگری را تغییر نمی‌دهد.

شواهد موفق بررسی داخل `.data/compose-workspace/reports/local-stack-verification.json` ثبت می‌شود. نبود این فایل یا اجرای ناموفق به معنی تأییدشدن جریان نیست.

## وضعیت، لاگ و توقف

```bash
npm run stack:status
npm run stack:logs
npm run stack:stop
```

توقف، داده را پاک نمی‌کند. برای رفع خطا volumes را حذف نکنید. رمزها را با ویرایش تصادفی فایل env عوض نکنید؛ رمز پایگاه موجود هم باید با روش مدیریت خود سرویس تغییر کند.
