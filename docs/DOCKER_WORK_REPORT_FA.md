# گزارش اجرای کار: زیرساخت محلی BI با Docker Compose

تاریخ: ۲ نوامبر ۲۰۲۶

## نتیجهٔ فعلی

پیکربندی و ابزارهای اجرای پشتهٔ کامل ساخته، در پروژه نصب و از نظر نحوی، TypeScript، آزمون و build بررسی شدند. Docker اکنون روی سیستم نصب است، اما نشست جاری هنوز اجازهٔ اتصال به socket آن را ندارد. تلاش واقعی `npm run stack:up` با خطای permission denied متوقف شد؛ بنابراین در این مرحله هیچ کانتینر، پایگاه دادهٔ داخل Docker یا داشبورد ناشی از این جریان ساخته و تأیید نشده است.

برنامهٔ میزبان روی پورت ۳۰۰۱ و حساب‌ها و دادهٔ آن حفظ شده‌اند. محیط جدید عمداً روی پورت ۳۰۰۳ و با دادهٔ مجزا تعریف شده است.

## کارهای انجام‌شده

- فایل compose.yaml برای PostgreSQL، Kafka تک‌گره‌ای KRaft، Kafka Connect با Debezium، ClickHouse و خود برنامه اضافه شد.
- Dockerfile با مرحلهٔ build، اجرای نهایی با کاربر node و مستثناکردن داده و رمزها از build context ساخته شد.
- برای PostgreSQL، WAL منطقی، نقش replication غیرمدیر و اسکریپت مقداردهی یک جدول سفارش مصنوعی آماده شد. این مقداردهی فقط روی volume خالی جدید انجام می‌شود.
- برای ClickHouse، پایگاه اختصاصی، رمز تصادفی، محدودیت منابع و تنظیم threadها تعریف شد.
- healthcheck و انتظار سلامت سرویس‌های وابسته، volumeهای پایدار و محدودیت انتشار درگاه‌های زیرساخت به loopback تعریف شدند.
- رمزهای خصوصی محلی با `stack:init` در میزبان ساخته شدند؛ رمزها در خروجی چت چاپ نشده‌اند.
- اسکریپت راه‌اندازی از منطق احراز هویت فعلی و APIهای دارای کنترل نقش استفاده می‌کند؛ endpoint عمومی مخفی یا حذف احراز هویت اضافه نشده است.
- دستورات وضعیت، لاگ، توقف بدون حذف داده، راه‌اندازی، راستی‌آزمایی و آزمایش درج/اصلاح/حذف اضافه شدند.
- راهنمای فارسی راه‌اندازی و قواعد نگهداری در docs/DOCKER_COMPOSE_FA.md و deploy/rule.md نوشته شدند.
- از فایل‌های قبلی پیش از تغییر، آرشیو در docs/before-compose-*.tar.gz گرفته شد.

## آنچه پس از رفع دسترسی توسط ابزار راه‌اندازی انجام می‌شود

۱. ساخت تصاویر و اجرای پنج سرویس و بررسی سلامت آن‌ها.
۲. مقداردهی bi_source و sales.orders با ۸ سفارش مصنوعی برای ۵ مشتری؛ این داده‌ها واقعیِ سازمان نیستند.
۳. ساخت حساب‌های local_provider و local_customer با رمزهای تصادفی خصوصی؛ این حساب‌ها مربوط به پورت ۳۰۰۳ هستند.
۴. تنظیم ClickHouse، Kafka Connect و منبع PostgreSQL در برنامه و کشف/نگاشت ستون‌ها.
۵. ایجاد connector، دریافت snapshot اولیه از Debezium و Kafka به ClickHouse و انتشار نسخهٔ داده.
۶. تعریف چهار KPI، تأیید ارائه‌دهنده و تطبیق دقیق با ارقام مستقل PostgreSQL.
۷. ساخت و انتشار گزارش با چهار کارت KPI و نمودارهای شهر، تاریخ، وضعیت و جدول مشتریان.
۸. راستی‌آزمایی نتیجهٔ پرس‌وجو و پنهان‌بودن تنظیمات زیرساخت برای مشتری.

این فهرست رفتار پیاده‌سازی‌شدهٔ اسکریپت است، نه ادعای انجام‌شدن این مراحل در محیط فعلی.

| bash -n برای مقداردهی PostgreSQL | موفق |
| تجزیهٔ XMLهای ClickHouse | موفق |
| lint اسکریپت TypeScript | موفق، بدون خطا یا هشدار |
| TypeScript برنامه و ابزار راه‌اندازی | موفق |
| مجموعهٔ آزمون فعلی | ۱۶۷ آزمون در ۱۱ فایل موفق |
| build تولید برنامه | موفق |
| اجرای واقعی stack:up | ناموفق: دسترسی Docker socket رد شد |
| سلامت کانتینرها و انتقال دادهٔ واقعی | هنوز اجرا نشده |

پس از موفقیت اجرای واقعی، مدرک خصوصی در `.data/compose-workspace/reports/local-stack-verification.json` نوشته می‌شود. صرف وجود فایل‌های Compose یا موفقیت آزمون‌های واحد، جای مدرک اجرای انتهابه‌انتها نیست.

## مانع و ادامهٔ کار

فایل socket اکنون مالک root، گروه docker و مجوز 660 دارد. کاربر navid در پایگاه گروه‌ها عضو docker است، اما نشست اجرای عامل هنوز گروه قبلی را دارد؛ ابزار newgrp/sg هم در این سیستم موجود نیست. sudo نیز به تأیید تعاملی شما نیاز دارد.

برای اجازهٔ محدود به گروه شخصی خودتان در همین نشست، روی رایانهٔ میزبان اجرا کنید:

```bash
sudo chgrp navid /var/run/docker.sock
```

این دستور socket را برای همه قابل‌نوشتن نمی‌کند و جایگزین chmod 666 نیست. روش پایدار معمول، ورود دوباره به نشست پس از عضویت در گروه docker است؛ با شروع مجدد daemon ممکن است گروه socket به docker برگردد.

سپس ادامهٔ اجرا:

```bash
cd /home/navid/work/powerBI/control-center
npm run stack:up
npm run stack:provision
npm run stack:exercise
npm run stack:verify
```

در صورت موفقیت، ورود به محیط جدید:

http://172.16.10.15:3003/fa/login

مشاهدهٔ رمزهای محلی، فقط روی میزبان:

```bash
cat .data/compose-access.txt
```

## محدودیت و مرز کار

این پشته، پایلوت محلی تک‌سازمانی با دادهٔ مصنوعی است. استقرار چندگره‌ای، HA، ورود سازمانی، TLS/SASL کامل Kafka، زمان‌بندی مداوم انتشار، مدل‌های حسابداری پیچیده و Microsoft Power BI/SSAS/PBRS جزو این کار نیستند. داشبورد بومی برنامه از ClickHouse می‌خواند. داده‌ها و حساب‌های برنامهٔ پورت ۳۰۰۱ به محیط جدید منتقل یا پاک نشده‌اند.
