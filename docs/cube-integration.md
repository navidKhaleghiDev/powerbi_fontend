# راهنمای اتصال به Cube

در برنامه، پنل **پیکربندی** و سپس صفحه **نمای کلی** را باز کنید. فرم اتصال در کارت **داده‌های Cube** قرار دارد.

## استفاده از رابط کاربری

۱. نشانی API را وارد کنید؛ برای اجرای محلی معمولاً `http://localhost:4000/cubejs-api/v1` است.

۲. اگر Cube در حالت توسعه محلی اجرا می‌شود، توکن را خالی بگذارید. در سایر محیط‌ها، توکن API معتبر وارد کنید؛ هرگز مقدار `CUBEJS_API_SECRET` را در فرانت‌اند قرار ندهید.

۳. دکمه **آزمایش اتصال و دریافت معیارها** را بزنید. برنامه با متد `meta()` مدل‌های قابل دسترسی را از Cube دریافت می‌کند. موفقیت این مرحله به معنی دریافت اطلاعات مدل است؛ برای تأیید دریافت داده مرحله بعد را انجام دهید.

۴. از فهرست **معیار**، معیار واقعی مدل خودتان را انتخاب کنید. برنامه با متد `load()` مقدار آن را دریافت و نمایش می‌دهد. دیگر به مدل نمونه `LineItems` نیاز نیست.

۵. برای درخواست دوباره داده، **تازه‌سازی** را بزنید. تازه‌بودن کش فرانت‌اند یک دقیقه است؛ دریافت دوره‌ای خودکار فعال نیست و این تنظیم کش سمت Cube را حذف نمی‌کند.

تنظیمات اتصال و توکن فقط در حافظه این کارت نگهداری می‌شوند. با خروج از صفحه یا بارگذاری مجدد باید اتصال را دوباره آزمایش کنید. توکن در localStorage ذخیره نمی‌شود. مقادیر اولیه فرم می‌توانند از متغیرهای محیطی Vite گرفته شوند.

## مقادیر اولیه اختیاری

در فایل `.env.local` ریشه پروژه:

```env
VITE_CUBE_API_URL=http://localhost:4000/cubejs-api/v1
VITE_CUBE_TOKEN=
```

پس از تغییر فایل محیطی، `pnpm dev` را دوباره اجرا کنید. متغیرهای Vite در مرورگر قابل مشاهده هستند؛ secret امضای Cube را در آن‌ها قرار ندهید.

## محدوده این اتصال

مسیر داده: **رابط کاربری ← API سرویس Cube ← معیار مدل ← مقدار نمایش‌داده‌شده**.

این فرم اتصال به سرور موجود را تنظیم می‌کند. نصب Cube، تعریف مدل‌ها و اتصال Cube به دیتابیس در سمت سرور انجام می‌شود. سایر پنل‌های فضای کاری به‌صورت خودکار از این اتصال داده نمی‌گیرند.

یک معیار بدون بُعد فقط یک مقدار برمی‌گرداند. نمودار روند نیاز به بُعد زمانی واقعی مدل، بازه زمانی و دانه‌بندی دارد.

## Local Docker Compose stack

The root `docker-compose.yml` starts the frontend, Cube.js, and the model-management API against an existing PostgreSQL database. It does not create or alter the database.

1. Copy `.env.compose.example` to `.env.compose`. Set the database credentials and a random management key with at least 24 characters. Keep the ignored `.env.compose` file private; use a read-only database account where possible.
2. Start the stack with `docker compose --env-file .env.compose up --build -d`.
3. Open the app at `http://localhost:8080`. Cube's API is available at `http://localhost:4000`; model files are stored in `cube/model`.
4. Stop the services with `docker compose --env-file .env.compose down`. This does not remove model files.

This is a local development setup: Cube development mode is enabled for schema discovery, and the published ports are limited to loopback. Do not expose it publicly or use it as a production authentication boundary. Cube loads model files from `cube/model`, mounted at its default `/cube/conf/schema` directory. The physical table browser works without models, but measures and queries require models created in the model builder. See the Docker Compose section in the root README for details.

## بررسی خطاها

- خطای شبکه: بررسی کنید Cube اجرا شده و نشانی آن از مرورگر قابل دسترسی است. localhost به رایانه‌ای اشاره می‌کند که مرورگر روی آن اجرا می‌شود.
- خطای احراز هویت: توکن معتبر و تنظیمات محیط Cube را بررسی کنید.
- خطای CORS: در سرور Cube دسترسی مبدأ فرانت‌اند را مجاز کنید.
- فهرست معیار خالی: مدل‌ها و مجوزهای Cube را بررسی کنید.
- خطای دریافت مقدار: ممکن است اطلاعات مدل قابل دسترسی باشد اما اجرای درخواست روی منبع داده شکست بخورد؛ پیام خطا و لاگ سرور را بررسی کنید.

## ساخت مدل از داخل برنامه

در کارت داده‌های Cube بخش «ساخت پیش‌نویس مدل Cube» قرار دارد و بدون اتصال به سرور هم قابل استفاده است:

۱. نام مدل و نام جدول واقعی دیتابیس را وارد کنید.

۲. معیار اضافه کنید: شمارش، مجموع، میانگین، کمینه، بیشینه یا شمارش یکتا. برای انواع غیر از شمارش، ستون یا عبارت SQL را وارد کنید.

۳. بُعدهای متنی، عددی، زمانی یا منطقی مورد نیاز را اضافه کنید.

۴. پیش‌نمایش YAML را بررسی و فایل را دانلود کنید. نام‌های تکراری و تعریف‌های ناقص قابل دانلود نیستند. اعتبارسنجی مرورگر ساختاری است و وجود جدول، ستون و صحت عبارت SQL را تأیید نمی‌کند.

۵. فایل را در پروژه Cube بررسی و با مدل‌های موجود ادغام کنید. برای ذخیره مستقیم، سرویس Express و پوشه مدل مشترک را مطابق راهنمای server/README.md تنظیم کنید. دکمه «ساخت مدل روی سرور» فایل جدید ایجاد می‌کند؛ فعال‌شدن مدل جداگانه بررسی می‌شود. بعد از بارگذاری مدل در Cube، دوباره دکمه آزمایش اتصال را بزنید.

## ساخت درخواست و نمایش نتیجه

بعد از دریافت اطلاعات مدل، از بخش «درخواست داده از Cube» معیار و در صورت نیاز بُعد گروه‌بندی را انتخاب کنید. می‌توانید یک فیلتر برابری روی همان بُعد و محدودیت ۱ تا ۱۰۰۰ ردیف تعیین کنید. «اجرای درخواست / تازه‌سازی» درخواست را ارسال می‌کند. JSON درخواست و جدول نتیجه در همان بخش نمایش داده می‌شوند. پیش‌نویس‌های محلی تا زمان اعمال روی سرور، در فهرست معیارهای قابل درخواست ظاهر نمی‌شوند.

## بک‌اند Express برای ساخت مدل

اکنون می‌توانید مدل جدید را از همین رابط روی سرور ذخیره کنید:

۱. فایل `server/config.example.env` را به `.env.server` در ریشه پروژه کپی کنید.

۲. `CUBE_MODEL_DIR` را روی مسیر واقعی پوشه مدل در میزبان Docker تنظیم کنید؛ همان پوشه باید داخل کانتینر Cube نیز mount شده باشد. سرویس هیچ دسترسی به Docker socket نیاز ندارد.

۳. یک کلید تصادفی حداقل ۲۴ کاراکتری برای `CUBE_MANAGEMENT_KEY` تعیین کنید. این کلید را در متغیرهای VITE قرار ندهید. `CUBE_SERVER_API_URL` باید از سمت Express قابل دسترسی باشد.

۴. در دو ترمینال `pnpm dev:server` و `pnpm dev` را اجرا کنید.

۵. در فرم ساخت مدل، کلید مدیریت را وارد کنید و «اعتبارسنجی در سرور» و سپس «ساخت مدل روی سرور» را بزنید. اعتبارسنجی ساختاری، وجود جدول یا صحت اجرای SQL را تضمین نمی‌کند.

۶. پس از ذخیره، «بررسی نمایش مدل در Cube» را بزنید. موفقیت ذخیره فایل با فعال‌شدن مدل یکی نیست. پس از دیده‌شدن مدل در Cube، اتصال را دوباره آزمایش و یک معیار را اجرا کنید.

مدل‌های موجود جایگزین یا ویرایش نمی‌شوند. برای تغییر مدل موجود فعلاً از روال مدیریت پروژه Cube استفاده کنید. پیکربندی تولید و اتصال دیتابیس همچنان در سرور Cube انجام می‌شود. جزئیات Docker، API و محدودیت‌ها در [راهنمای بک‌اند](../server/README.md) آمده است.

## مشاهده جدول‌های واقعی دیتابیس

در **پیکربندی ← نمای کلی ← داده‌های Cube ← ساخت مدل**، کلید مدیریت را وارد کنید. در بخش **جدول‌ها و ستون‌های دیتابیس** دکمه دریافت جدول‌ها را بزنید، نام جدول را جست‌وجو و انتخاب کنید. ستون‌ها، نوع داده و کلید اصلی نمایش داده می‌شوند. دکمه «استفاده از این جدول در فرم ساخت مدل» نام جدول را در فرم قرار می‌دهد؛ هنوز هیچ مدل یا جدولی ساخته نمی‌شود.

این قابلیت اطلاعات ساختاری منبع داده پیش‌فرض Cube را از API توسعه محلی دریافت می‌کند؛ ردیف‌های جدول را نمی‌خواند. متغیر `CUBE_SCHEMA_DISCOVERY_URL` در `.env.server` باید روی آدرس `/playground/db-schema` سرور Cube محلی تنظیم شود. در محیط تولید یا نسخه‌ای که این endpoint را ندارد، سرویس خطای واضح برمی‌گرداند و به اتصال متادیتای جداگانه نیاز است.

## نمای کلی جدید فضای کاری Cube

صفحه نمای کلی اکنون به جای کارت‌های آماری فضای کاری محلی، چهار بخش دارد:

- **اتصال**: آدرس API، توکن اختیاری و کلید مدیریت را اینجا وارد کنید. کلیدها فقط در حافظه صفحه نگهداری می‌شوند.
- **مدل داده و جدول‌ها**: جدول‌ها در درخت schema نمایش داده می‌شوند. با انتخاب جدول، ستون‌ها را ببینید و نام جدول را به فرم مدل منتقل کنید. ساخت مدل همچنان از طریق اعتبارسنجی و ایجاد فایل جدید انجام می‌شود.
- **فایل‌های مدل**: فایل‌های واقعی Cube به صورت فقط‌خواندنی دریافت می‌شوند؛ فایلی انتخاب کنید تا محتوایش را ببینید. این بخش فایل موجود را تغییر نمی‌دهد.
- **محیط اجرای درخواست**: بعد از آزمایش اتصال، معیار، بُعد، فیلتر و بُعد زمانی واقعی را انتخاب کنید. برای بُعد زمانی، دانه‌بندی و بازه اختیاری تعیین کنید. پس از اجرا، نتیجه را به صورت جدول یا نمودار خطی/میله‌ای ببینید. JSON مربوط به آخرین درخواست نیز قابل مشاهده است. مقادیر خالی یا اعداد خارج از محدوده امن جاوااسکریپت به عنوان نقطه عددی نمودار نمایش داده نمی‌شوند؛ جدول مقادیر خام را نگه می‌دارد.

این ساختار با تصاویر مرجع هم‌راستا است؛ امکانات پیشرفته Cube مثل rollup، مدیریت security context، ویرایش مستقیم فایل و چند درخواست هم‌زمان در این نسخه پیاده‌سازی نشده‌اند.

### Environment-only SPA connection

The overview uses `VITE_CUBE_API_URL` and `VITE_CUBE_TOKEN` automatically; there is no connection form. Set them in `.env.local` (or `.env`) and restart Vite. Rebuild the SPA when changing production values. No request is made when the URL is unset; the UI displays an unavailable-configuration message. An empty token is supported for a Cube development server.

`VITE_` values are visible in the browser bundle. Only use a Cube token intended for browser access; never put a Cube API signing secret or the model management key here.
