# Frontend workspace rules

- This project contains UI only. Do not add API routes, server-side storage, database clients, ingestion workers, or infrastructure provisioning. Frontend requests may use only explicitly documented backend contracts through the shared API client; the server remains responsible for authorization and persistence.
- Authentication is a frontend client flow: login and refresh use the configured API base URL, access and refresh tokens are stored in local storage, protected API requests use bearer authorization, and logout clears tokens and cached server state. This UI state is not an authorization boundary.
- The CDC data-flow pages use the configured database-types, connection-test, tables, columns, and connector endpoints. The tables endpoint returns schema-qualified table-name strings; normalize them before rendering and send each selected qualified name in its own columns request. Send all selected qualified table names joined by comma and space in `table.include.list`. The GET connector endpoint can return a flat array of connector-name strings or rows of strings; treat each flat string as its own connector and each nested row as one connector, rendering their values without assuming undocumented field names. The first string in each row is used as the connector name for the documented config retrieval and delete routes because those routes require a name and the list contract does not label its fields. Keep source credentials in page memory and send them only in the documented request bodies; never add them to local storage or demo fixtures.
- Workspace contracts describe presentation data only. Never treat client-side state or UI visibility as authorization.
- The CDC connections page opens a dedicated ClickHouse consumer page from each connector. Read its database name from `database.dbname` and its source table list from comma-separated `table.include.list`. Ask the user for the source database username and password before retrieving selected-table columns through the database-columns endpoint; keep those credentials only in page-scoped React context and never persist them. Create consumers through `POST /api/consumer/` with `db_type: "clickhouse"`, a user-provided `topic.prefix`, and each source table's target table, column mappings (`source`, `target`, `type`), and selected `order_by` target columns.
- Start with empty workspace lists except for explicitly requested development fixtures in the Reports panel. Those fixtures must be development-only, clearly labeled fictional, isolated from Configuration, and excluded from production. Never represent fixtures as live PBRS/SSAS/LDAP, CDC, or warehouse integrations.
- CSV parsing and preview run in the browser with UTF-8 quoted-field support and limits of 2 MiB/5,000 rows. Preview does not import or publish data.
- Server-dependent actions must explicitly report unavailability and must never pretend to save or publish.
- Keep English/Persian message parity, strict TypeScript, named component exports, and TanStack Query interfaces for future server-state integration.
- Preserve the shared loading skeleton without edits.
- Reports and maps remain presentation components. Explicitly mapped WGS84 fields are required for maps; do not infer locations or add arbitrary tile URLs.
